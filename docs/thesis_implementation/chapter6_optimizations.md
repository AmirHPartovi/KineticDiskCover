# Chapter 6 preprocessing and optimization audit

This table was extracted from Chapter 6 of the local thesis PDF and
cross-checked against its source text,
`Chapters/06_Static_Implementation.tex`. Chapter 6 starts at PDF page 176 /
printed page 160. References below use the chapter's labels and equation
numbers; page ranges are PDF / printed pages.

The base model is single coverage with no station capacities. `D(t)`,
`D^-(I)`, and `D^+(I)` are distinct weighted-matrix inputs. A matrix-level
rule may be run independently on any one of them only when its condition is
checked on that exact matrix. A result established at one time or on one
interval is not reusable on another input without a fresh proof/check.

### Single-coverage scope

Lemma 6.2 row dominance is not generally valid in multi-cover: moving a point
from one of two distinct covering stations to the other can reduce the number
of distinct covers. Lemma 6.3 point aggregation is only transferable to a
multi-cover variant with equal requirements and its own proof. No multi-cover
or station-capacity feature is introduced.

## Implemented feature flags and speed-only effects

`WeightedPreprocessingOptionsV1` independently gates each implemented rule:
`radius_square_upper_bounds`, `equal_row_symmetry_breaking`,
`objective_lower_cut`, `station_dominance`, and `point_dominance`.
All default to false. The transformations are available as a separate
weighted-matrix utility; they are not silently injected into `D(t)`, `D^-`,
`D^+`, existing Oracles, or serialized station data.

The q caps and objective cut preserve the optimum value but are redundant
model inequalities; they can affect solver behavior only. Symmetry breaking,
station dominance, and point aggregation reduce equivalent search/model
choices while preserving optimum value; assignment identity may change.
Warm starts can improve a backend's search only if a caller actually passes
them to a backend. The existing `ILPSolver` API has no MIP-start parameter, so
the helper is not integrated into a live solve. The cache helper can avoid
repeated work only after a caller integrates it; no speedup is claimed.
No implementation feature changes the temporal Model A objective or issues a
new lower-bound certificate.

Incumbent fixing is intentionally not exposed as an enabled flag: the present
code cannot independently validate the same-matrix incumbent upper bound that
the rule requires. Approximate dominance and KDS remain unavailable.
